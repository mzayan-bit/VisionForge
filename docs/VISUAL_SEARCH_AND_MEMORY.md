# VisionForge Visual Memory & Visual Search Engine Architecture

The VisionForge **Visual Memory System** and **Visual Search Engine** provide dense vector indexing, storage persistence, and similarity search over 768-dimensional image embedding vectors generated by the Embedding Engine (`siglip-base-patch16-224`).

---

## 1. Visual Memory Core (`visionforge.memory`)

### In-Memory Vector Store & Disk Persistence
- **Storage Layout:** `~/.cache/visionforge/memory/visual_memory_index.json`.
- **Atomic Operations:** Add, update, lookup, delete, list, clear, save to disk, and auto-restore on boot.
- **Record Schema (`VisualMemoryRecord`):**
  - `id`: Unique record string identifier.
  - `embedding`: 768-dimensional float32 vector.
  - `dimension`: 768.
  - `image_metadata`: Width, height, format, mode, aspect ratio, file size.
  - `tags`: List of search classification tags.
  - `indexed_at`: ISO 8601 creation timestamp.

---

## 2. Visual Search Engine (`visionforge.search`)

### Similarity Metrics
The search engine supports three mathematical distance metrics:

1. **Cosine Similarity ($\mathbf{S}_{\text{cos}}$):**
   $$\mathbf{S}_{\text{cos}} = \mathbf{V}_{\text{index}} \cdot \mathbf{v}_{\text{query}}^\top$$
   *(Since vectors are $L_2$-normalized, dot product equals cosine similarity).*
2. **Dot Product ($\mathbf{S}_{\text{dot}}$):**
   Unscaled vector inner product.
3. **Euclidean ($L_2$) Distance ($\mathbf{d}_{\text{euc}}$):**
   $$\mathbf{d}_{\text{euc}} = \|\mathbf{V}_{\text{index}} - \mathbf{v}_{\text{query}}\|_2$$
   Similarity score mapped to range $[0, 1]$ via $1 / (1 + \mathbf{d}_{\text{euc}})$.

## 3. REST API Endpoints

### Memory Subsystem (`/api/v1/memory`)
- `POST /api/v1/memory/index` — Upload image file $\rightarrow$ run SigLIP embedding pipeline $\rightarrow$ store in Visual Memory Index.
- `GET /api/v1/memory/stats` — Return total indexed vectors, dimension, memory size MB, and persistence telemetry.
- `GET /api/v1/memory/records` — Return paginated list of indexed visual memory records.
- `DELETE /api/v1/memory/clear` — Purge all indexed vectors from memory and disk.

### Search Subsystem (`/api/v1/search`)
- `POST /api/v1/search/image` — Upload query image $\rightarrow$ extract embedding $\rightarrow$ search Visual Memory $\rightarrow$ return ranked Top-$K$ matches with similarity scores.
- `POST /api/v1/search/vector` — Perform similarity search directly using a 768D query vector.

---

## 4. Performance & Scalability

- **Vectorized NumPy Operations:** Similarity matrices are calculated in C-speed vectorized NumPy operations (`np.dot`).
- **Memory Footprint:** 10,000 vectors (768D float32) consume only **~30.7 MB** RAM.
- **Future Vector Database Plug-in:** Abstracted behind `VisualMemoryIndex` so enterprise indices (Qdrant, FAISS, Milvus, pgvector) can be swapped in without modifying the API layer.
